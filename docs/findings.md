# Findings

Compiled 17 November 2026, from a design pass on a real static site. Everything
below was either measured in a browser or cost a bug. The traps are the valuable
half.

## 1. What was actually studied

**A short-form design reel** (@ayoships, 1 October 2026). Worth being precise
about: the video frames were not readable, only the post's metadata and comments.
Every comment is tagged "3d", and the one that names the problem is:

> "the default layout works, it just never makes anyone remember the brand"

That single line was the useful part. It is a diagnosis, not a technique: a page
is not forgettable because its colours are wrong, but because every screen has
the same structure — a band, a centred heading, a row of identical boxes. The fix
is a focal point and a rhythm, not more decoration.

**GitHub repositories surveyed:**

| Repo | What it offered | Taken? |
|---|---|---|
| `css-scroll-driven/css-scroll-driven` | Native `animation-timeline: view()` patterns, plus accessibility notes | Approach only — see §4 |
| `you-dont-need/You-Dont-Need-JavaScript` | Pure-CSS 3D (cube, pyramid, flip cards) | Technique: `perspective` on the parent |
| `rskworld/css-3d-gallery` | Catalogue of 3D card treatments: tilt, flip, parallax layers | Tilt ranges, nothing else |
| `lindelof/awesome-web-effect` | Long list of JS effects libraries | Rejected: dependencies |
| `awesome-css-group/awesome-css` | Style guides and frameworks | Rejected: not a technique |
| `cssanimation/css-animation-101` | Animation fundamentals | Background only |

**3D website writing** (Webflow, Motion.dev, LogRocket, Effect.Labs, Polypane,
ICS Media) agreed on the mechanics and disagreed on nothing important:

- `perspective` belongs on the parent; `perspective-origin` moves the camera.
- `transform-style: preserve-3d` belongs on the element whose children need depth.
- `translateZ` is what makes depth exist; `backface-visibility` hides the back face.
- Real 3D sites use WebGL for models. **This template does not**, because WebGL
  means a library or hundreds of lines of shader code, and the projects using
  this are static pages that must open from a memory stick.

## 2. The diagnosis, applied

A page reads as generic when:

1. every section has the same shape and the same vertical rhythm;
2. there is no focal point on the first screen;
3. all surfaces have the same depth — one flat drop shadow, or none;
4. nothing changes as you scroll, so the page has no sense of length or place.

Four cheap fixes, in order of impact per line of code:

1. **One 3D focal point**, not twenty. The hero tilts; the rest of the page is calm.
2. **Numbers on sections**, generated by CSS counters. A 27-section page suddenly
   has a shape you can feel while scrolling.
3. **A shadow stack** (hard offset + soft ambient + inset top highlight) instead of
   one flat drop. This is most of the difference between "styled" and "designed".
4. **Cards that lift** by 4px on hover, and only on a pointer.

## 3. The techniques, with code

### 3.1 The scene

```css
.scene  { perspective: 1100px; }              /* the camera, on the parent */
.stage  { transform-style: preserve-3d; }     /* children keep their own depth */
.pop    { transform: translateZ(48px); }      /* a second depth */
```

900–1200px of perspective is the usable range. Below 800 the edges stretch and
text blurs; above 1400 the effect disappears.

### 3.2 Pointer tilt

Map pointer position to `rotateX`/`rotateY`, clamped, one `requestAnimationFrame`
per move:

```js
var px = (event.clientX - box.left) / box.width - 0.5;   // -0.5 .. 0.5
var py = (event.clientY - box.top) / box.height - 0.5;
x = clamp(px * maxX * 2.2, -maxX, maxX);
y = clamp(-py * maxY * 2.2, -maxY, maxY);   // negative: push down, tilt up
```

Five degrees horizontal and four vertical is the ceiling for anything with text
near it. Ten degrees is a fairground ride.

### 3.3 The sticker

One element at a second depth, deliberately hanging over the card edge. It is
what makes the scene read as layered rather than rotated. Keep it to one.

Its colours should be **literal**, not themed: a sticker sits on artwork, and if
the artwork stays light in a dark theme, a themed sticker becomes a dark hole
punched in the middle of a pale picture.

### 3.4 The halo

```css
.halo { box-shadow: 0 30px 50px -32px rgba(94,60,20,.55),
                    0 0 70px -6px rgba(242,177,52,.45); }
```

Warm light behind the artwork, done as a shadow. See trap 2 for why it is not a
blurred element.

### 3.5 Section numbering from counters

```css
main        { counter-reset: band; }
section[id] { counter-increment: band; position: relative; }
section[id]::before {
  content: counter(band, decimal-leading-zero);
  position: absolute; top: 16px; right: max(20px, calc((100% - 1140px) / 2));
  font-size: clamp(3rem, 6.5vw, 4.8rem);
  opacity: .09; color: currentColor; pointer-events: none;
}
```

Zero markup changes. Add or remove a section and the page renumbers itself. The
phone version drops the giant numeral for a 0.7rem label above the heading,
because a 77px number over 20px body text on a 390px screen is a mess.

### 3.6 Scroll-driven reveal, as progressive enhancement

From `css-scroll-driven`, this is the modern way and needs no JavaScript:

```css
@supports (animation-timeline: view()) {
  .rise {
    animation: rise linear both;
    animation-timeline: view();
    animation-range: entry 10% cover 28%;
  }
  @keyframes rise { from { opacity: 0; transform: translateY(14px); } }
}
```

It runs on the compositor, so it cannot jank the main thread. The `@supports`
block means browsers without it simply show the content — which is the correct
failure for a reveal animation.

**Not shipped in `3d.css`**: a reveal class driven by `IntersectionObserver` is
used instead, because a reveal must also be undone for print. Anything held at
`opacity: 0` prints blank. The hidden state is applied only after `scene.js`
marks the document, so a page with no script shows every card.

### 3.7 A hero with layers that leave the page

One scene, three depths, and artwork that runs off the right edge. The camera is
on the parent; the stage holds the layers; nothing else is needed.

```css
.hero   { overflow: hidden; }                  /* the window */
.scene  { perspective: 1400px; perspective-origin: 62% 42%; }
.split  { display:flex; min-height:700px; transform-style: preserve-3d; }
.copy   { width:50%; transform: translateZ(90px); }     /* nearest */
.photo-main { position:absolute; right:-9%; width:55%;
              transform: rotateY(-9deg) rotateX(2deg); }
.photo-back { position:absolute; left:52%; bottom:2%; width:22%;
              transform: translateZ(-130px) rotateY(-6deg); }
.sticker    { transform: translateZ(190px) rotate(-8deg); }  /* furthest */
```

Three things make it read as depth rather than as a rotated picture:

1. **The main photo hangs off the edge.** `right: -9%` with `overflow: hidden`
   on the window, not on the stage. A frame that stops politely at the column
   edge reads as a screenshot.
2. **A second photo sits further back than the frame.** Without something
   behind the front layer, `rotateY` on it is just a skew.
3. **The copy column is capped at 50%.** Measured: the copy's right edge was
   713px and the photo's left edge 769px at 1440px wide. A sentence that crosses
   a photograph is unreadable, and no amount of depth makes it readable.

The scroll recede is the cheapest sense of place on a long page. The stage is
pushed back along z as the hero leaves:

```js
var top = scene.getBoundingClientRect().top;   // 0 at rest, negative after
var z = Math.max(-240, Math.min(0, Math.round(top * 0.45)));
stage.style.transform =
  "rotateX(" + rx + "deg) rotateY(" + ry + "deg) translateZ(" + z + "px)";
```

Measured on the source page: `translateZ` 0 at scroll 0 and 200, -91px at 420,
-217px at 700. The cap matters: uncapped, a long page ends up as a zoom. The
sign matters more — see trap 6.

## 4. The eight traps

All eight were hit for real; six of them cost a visible bug. The eighth was found
by measuring the demo rather than by shipping it, which is the cheaper way to
find one.

### Trap 1 — `perspective` on the child

Put `perspective` on the element you are rotating and every child gets its own
vanishing point. A row of rotated cards then looks subtly wrong in a way nobody
can name. It belongs on the parent.

### Trap 2 — a blurred box as a halo

```css
/* This gives a phone a horizontal scrollbar. */
.glow { position: absolute; inset: -6% -14% -10% -12%; filter: blur(34px); }
```

The element is 14% wider than its parent, so the document becomes wider than the
viewport: 390px viewport, 409px document, 19px of sideways scroll. `overflow:
hidden` on the wrapper fixes the scrollbar and clips the glow you wanted.

Use `box-shadow`, which is never part of the scrollable area. Same glow, no price.

### Trap 3 — `translateZ` inside a flattened parent

If an ancestor sets `filter`, `opacity < 1`, `overflow: hidden` or
`backdrop-filter`, the 3D context flattens and `translateZ` silently does nothing.
`transform-style: preserve-3d` must survive all the way up the chain.

### Trap 4 — backdrop blur above a fixed drawer

```css
.topbar { backdrop-filter: blur(14px); }   /* mobile drawer escapes to the bar */
```

`backdrop-filter` (like `filter`) makes its element the containing block for
fixed-position descendants. On a phone the nav *is* fixed, so the drawer gets
pinned to the header instead of the screen. Scope the blur:

```css
@media (min-width: 761px) { @supports (backdrop-filter: blur(6px)) { ... } }
```

### Trap 5 — depth on text

Tilt is fine on artwork and card chrome. On body copy it costs real readability:
the glyph stems blur at the extremes, and readers with visual stress notice first.
Keep reading text flat and upright, and cap any tilt near text at a few degrees.
A short hero column is the one exception, and it is short for this reason.

### Trap 6 — the scroll recede with the wrong sign

The recede is one line, and written the obvious way it goes the wrong way:

```js
// Wrong: z grows positive as the hero leaves, so the scene zooms AT the reader.
var z = Math.round(scene.getBoundingClientRect().top * -0.45);

// Right: zero at rest, negative once the hero starts up the screen.
var z = Math.max(-240, Math.min(0, Math.round(top * 0.45)));
```

`getBoundingClientRect().top` is positive while the hero is below the fold and
negative once it has scrolled past. A page that only checked the effect at rest
looks perfect, because at rest the value is zero. It was caught by reading
`getComputedStyle(stage).transform` at four scroll offsets, not by looking at a
screenshot.

Two related notes worth keeping next to it:

- **Clip the window, not the stage.** `overflow: hidden` on the element with
  `perspective` is fine — that is an ancestor clipping its child. `overflow:
  hidden` **on** the preserve-3d stage flattens its own children, and every
  `translateZ` silently stops doing anything.
- **`will-change: transform` on the stage is a hint, not a fix.** It promotes
  the layer and keeps the recede off the main thread's paint, but it also costs
  memory per promoted layer. One per page is fine; one per card is not.

### Trap 7 — a lifted photo in a grid is projected sideways

Found while porting the card photo into this template, so it is the one trap
here that never shipped on the source page.

```css
.cards { perspective: 1100px; }                /* one camera, at grid centre */
.card-photo { transform: translateZ(30px); }   /* moves 12px out of the card */
```

`perspective` on the container puts the camera at the centre of the **grid**.
A child at `translateZ` is projected away from that point, so a photo in the
first card slides left and the photo in the last card slides right. Measured at
1440px: card left edge 143px, its photo's left edge 131px — a 12px overhang
outside the card's own border, with a matching gap on its right. The middle
card looks perfect, which is why a screenshot of one card would never show it.

The fix is not a bigger grid or a smaller lift, it is to stop lifting the
photo: a full-bleed photo at the card edge and a shared camera cannot both be
flush and forward-facing. The card itself still tilts, and that is where the
depth reads.

If you genuinely need the photo to separate, give the card its own
`perspective` so the camera is at the card's centre, and inset the photo inside
the card padding (roughly 3% of its width is added on each side at 30px), so
the expansion lands on padding instead of on the page.

### Trap 8 — a lifted text column is projected out of its container

```css
.scene { perspective: 1100px; perspective-origin: 62% 42%; }
.copy  { width: 50%; transform: translateZ(90px); }
```

A camera whose origin is not at the centre projects every lifted child **away
from that origin**. The copy column rides 90px forward, so it is projected left
by

```
lift / (perspective - lift) x origin = 90 / 1010 x 62% = 5.5% of the scene
```

which is 63px on a 1140px scene. On a wide page the gutter absorbs it. At
1024px the gutter is 20px, so the column started at **-33.5px** and the first
~33px of every hero line was outside the page. Measured: -31.2px at 981,
-33.5px at 1024, -37.7px at 1100. Above 1280 it is 63px, which the gutter
finally covers.

Nothing caught it. `scrollWidth` still equalled `clientWidth` at every one of
those widths, because `.t3-hero` clips the photo that bleeds off the right edge
and clips the text that bleeds off the left one with the same rule. The overflow
check passed on a page that was losing the start of every sentence in its hero.
It was found by measuring the `h1`'s bounding box, not by looking at the page.

Two ways out, and the first is better:

- **Do not lift reading text.** Push the artwork back instead — the arrangement
  in `photographs.md` § 2.1, where the photograph sits at -150px with
  `scale(1.16)` and the words stay flat at 0.
- **Cancel the projection with a pad.** The pad is a percentage of the *scene*,
  not of the column, because percentage padding resolves against the containing
  block; and the pad is then projected by the same factor:

```
pad = 5.5% / 1.089 = 5.1%
```

  That is `--t3-copy-inset`. Measured after the fix: the text begins 0.3px inside
  the scene's left edge at 981, 1024, 1100, 1280, 1440 and 1920.

It is trap 7's mechanism — a shared camera projecting a lifted child sideways —
with a worse symptom. Trap 7 moved a photo 12px over a border. This one deletes
the first two letters of every line in the hero, silently, on a page that reports
no overflow.

## 5. The accessibility contract

- **Motion is opt-out, twice.** JS checks before binding; CSS refuses the
  transform again under `prefers-reduced-motion` and `(pointer: coarse)`. The
  scroll recede never binds at all in either case.
- **A reveal is progressive.** Cards are hidden only after the script marks the
  document, so a browser without it sees the content, not a blank column.
- **Nothing critical depends on depth.** Flatten the page and every number, card
  and sticker is still there and still legible.
- **Contrast at 4.5:1 minimum for normal-size text.** Depth makes this easy to
  break: white on a mid-tone accent measured 3.4–4.4:1 in the source project.
  Darken the accent, not the text.
- **Print is a real output.** Force reveals visible, hide stickers and pops, kill
  every transform.
- **`prefers-contrast: more`** drops the decorative halo.

## 6. What was deliberately not taken

- **WebGL / three.js.** One dependency, one build step, one more thing that fails
  from a memory stick.
- **Libraries** (`vanilla-tilt.js`, `react-tilt`, `hover3d`). The whole effect is
  ~40 lines; a library would be the larger file.
- **Scroll-jacking and parallax on text.** It fights the scrollbar and it makes
  reading a long page worse, which is the opposite of the goal.
- **Cubes.** Every 3D CSS tutorial builds a rotating cube. No reader has ever
  wanted one.
